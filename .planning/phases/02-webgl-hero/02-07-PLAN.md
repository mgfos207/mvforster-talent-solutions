<objective>
Close VERIFICATION.md gap 1. The still is supposed to equal the live t=0 frame (D-05/D-06), but on real devices it does not. The mobile still is rendered at CSS 780px, which falls in the tablet node tier (36 nodes), yet it is only served below 768px, where the live canvas uses 22 nodes. The same problem affects the desktop still: it is also served at 768-1023px, where the live canvas uses the tablet tier.

The fix has three parts:
1. Each still variant now has its own render CSS size, dpr, and served range, all in heroConfig.
2. A tablet still is added so that every served range maps to exactly one node tier.
3. Mobile is rendered at CSS 390x844 with dpr 2.

Tests and a harness diff mode make any future tier mismatch fail loudly.

Desktop non-16:9 decision (Claude's discretion, gap item 2): use documented acceptance, not live cover-fit projection. A cover-fit projection would mean reworking the gradient shader's aspect math and nodeNetwork's normalized-coordinate model. The original design deliberately chose full-container normalization for live interaction, and UAT approved that. The guarantee after this plan:
- Node count, link distance, and point size match on every served viewport.
- The pixel-exact match holds at each variant's reference CSS size.
- At other aspect ratios within a tier, the object-cover crop shifts node positions by a bounded amount during the 800ms crossfade.

Purpose: D-05/D-06 "imperceptible crossfade" on the devices actually served each still.
Output: extended still config, tests, a dpr-aware harness with --verify-stills, three regenerated stills, and a config-driven Hero.tsx <picture>.
</objective>
